# Freight Invoice Audit Engine — Source Manifest & Lawful Provenance

## 1. Provenance Statement & Lawful Data Use

All records generated by the Freight Invoice Audit System are **100% synthetically generated** using deterministic procedural algorithms and mathematical models reflecting standard North American freight transportation conventions.

- **No Personally Identifiable Information (PII):** Carrier names, contact emails, and personnel designations are fictitious corporate identifiers (e.g. `Apex Express #1`, `billing@apexexpress.com`).
- **No Confidential or Proprietary Shipper Data:** Rates, lanes, distances, and freight charges are synthesized according to published NMFC (National Motor Freight Classification) LTL density tiers and EIA diesel fuel index ranges.
- **Lawful Provenance:** No external web scraping, paywalled database queries, or proprietary EDI feeds were accessed. All schema structures draw exclusively from open commercial transport paradigms (ANSI X12 210 Freight Details & Invoice, 204 Motor Carrier Load Tender).

## 3. Seed Commands

### Generating Starter Dataset
```bash
python scripts/run_generator.py --scale starter --seed 20261022
```
Outputs to `data/starter/` with CSV, JSON, and SQLite database `freight_audit.db`.

### Generating Full Scale Dataset (100 carriers, 20k shipments, 15k invoices)
```bash
python scripts/run_generator.py --scale full --seed 20261022
```
Outputs to `data/full/` with 168,808 rows across all 11 core entities.

### Verifying Reproducibility (Step 10)
```bash
python scripts/verify_reproducibility.py
```
Regenerates twice in isolated temporary paths and validates byte-for-byte identical SHA-256 hashes.

## 4. Ground Truth Isolation (Step 7 Verification)

In accordance with Step 7 of the problem statement:
> *"Produce a separate ground_truth.csv/json for known anomalies, expected decisions or labels; never leak it into input features."*

- Input tables (`freight_invoices`, `invoice_lines`, `shipments`, `rate_cards`) contain **zero** target labels, ground truth columns, or anomaly flags.
- All injected negative cases are tracked in an isolated registry exported strictly to:
  - `data/starter/ground_truth.csv`
  - `data/starter/ground_truth.json`
  - `data/full/ground_truth.csv`
  - `data/full/ground_truth.json`
- Each ground truth record records:
  - `target_entity` (e.g. `FreightInvoice`)
  - `target_id` (e.g. `FINV-2026-000015`)
  - `anomaly_category` (e.g. `SURCHARGE_DUPLICATED`)
  - `expected_decision` (`AUDITED_EXCEPTION`)
  - `expected_variance` (financial discrepancy in USD)
  - `line_number` (optional line index)
  - `explanation` (root-cause rationale)
